# WS2812 SPI DMA Driver Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Replace the WS2812 RMT transport with SPI2 DMA while preserving display behavior and bounded recovery.

**Architecture:** Encode each GRB bit as a 3-bit SPI symbol (`0=100`, `1=110`) at 2.5 MHz. A dedicated SPI2 bus drives MOSI on GPIO10 with no external clock, chip-select, MISO, or wiring changes. Transfers use DMA-capable buffers and queued transactions; a timeout leaves the transaction owned by the driver until a later poll confirms completion, after which recovery/retry is safe.

**Tech Stack:** ESP-IDF 5.3.4 SPI master, SPI DMA, FreeRTOS ticks, heap capabilities, existing WS2812/display diagnostics APIs.

**Spec:** User-approved SPI+DMA transport replacement design in the conversation.

## Global Constraints

- Keep GPIO10, 16x16 mapping, RGB frame API, animations, status lamp, health checks, and NVS diagnostics unchanged.
- Do not use RMT, `led_strip_refresh`, or unbounded waits.
- Keep the existing recovery backoff and only publish `s_displayed_frame` after a confirmed successful transfer.
- Do not erase NVS or flash the device.
